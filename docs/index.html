01 The claim

Correctness is a diff, not an opinion

The test corpus is declared as data in spec.py — every page, redirect, duplicate and trap. A second module derives the expected result from that declaration, touching no HTTP and parsing no HTML. A crawl is correct when the set it found equals the set that was declared. Nothing else counts, and the ground truth is never edited to make a crawl pass.

03 robots.txt

Four hosts, four different answers

RFC 9309 says an unreachable robots.txt is not permission. A 4xx means the site has no rules and you may crawl freely; a 5xx or a timeout means you may crawl nothing. The corpus serves all four cases on four ports so the rule can be tested rather than assumed.

Hostrobots.txtEffectDisallowedCrawl-delay

Longest match wins, not first match — and Allow: beats Disallow: when it is more specific, which is why /private/public-corner is fetched while /private/secret is not.

04 Normalisation

Fourteen spellings of one page

The corpus links to /a fourteen different ways. A crawler that treats them as distinct fetches the same document fourteen times; one that over-normalises invents URLs the server will not serve. The right answer is three fetches — two genuinely distinct URLs, plus one redirect the server resolves itself.

Trailing slashes are not stripped. /docs/ and /docs are different resources to a server, and an earlier version of this rule invented 404s by assuming otherwise. The corpus now answers /a/ with a 301 so the crawler learns the equivalence from the server instead of guessing it.

05 Duplicates

Same document, different URL

Three kinds, three mechanisms. Byte-identical pages collapse on a SHA-256 of the body. Near-duplicates are caught by simhash — a 64-bit fingerprint where similar documents differ in few bits — with banded matching so the comparison is not quadratic. A <link rel=canonical> is a third kind: the site telling you two URLs are one page.

06 The archive

What the crawl left behind

Every response is written to a WARC 1.1 file — the format the Internet Archive and Common Crawl use — with each record as its own gzip member. That framing is what makes the file seekable: the bytes of one record decompress alone, with nothing before them read.

07 Lookup

  
Finding one record without reading the file

  
The index is a sorted text file, so a lookup seeks to a byte midpoint, scans to the next newline, compares, and recurses on a half — never loading the index. The key is a SURT: host labels reversed, so every URL under a domain sits in one contiguous run. 08 Replay

  
The same links, with the server switched off

  
An archive you can write but not read is a backup nobody has ever restored. Replay seeks to each record, rebuilds the HTTP response and hands the body to the same parser the live crawl used — no socket, no robots check, no politeness wait.

  

  
The test poisons socket.connect for the duration rather than killing the server, because a stale listener on the port could let a kill-based test pass by accident.






  
09 The real web

  
What a self-written corpus could never find

  
Twelve stages passed against a corpus that was entirely UTF-8 — so parse() assumed UTF-8, and nothing ever noticed. Pointing the crawler at real sites found it in minutes. It hid because link extraction survives mojibake: hrefs are ASCII, so a mangled page yields exactly the right links and the crawl looks perfect while every title, word count and duplicate-detection fingerprint is quietly corrupted.

  

  

    
The fix is a stated precedence — BOM, then the HTTP header, then <meta charset>, then strict UTF-8, then windows-1252, which decodes every possible byte and therefore cannot fail. The header and meta are decoded strictly on purpose: a page that declares UTF-8 and is not is common, and a strict failure is the only evidence that the declaration lied.
